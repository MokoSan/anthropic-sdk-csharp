Anthropic C# SDK, top-level constructs

A guided map of the public surface: the client you construct, the services hanging off it, the request and response types they trade in, and the helpers, errors and platform clients built around them. Every snippet below is taken from, or checked against, the cloned repo.

AnthropicClient

src/Anthropic/AnthropicClient.cs · IAnthropicClient.cs · Core/ClientOptions.cs

The single entry point. AnthropicClient implements IAnthropicClient (use the interface for DI and mocking) and is IDisposable because it owns an HttpClient. The parameterless constructor resolves credentials and base URL from the environment; the ClientOptions overload takes them explicitly.

MemberWhat it does
ApiKey, AuthTokenSent as x-api-key or Authorization: Bearer. Default from env vars.
BaseUrlDefaults to the first-party API, or ANTHROPIC_BASE_URL.
MaxRetries, TimeoutDefaults 2 retries and 10 minutes (ClientOptions.DefaultMaxRetries, DefaultTimeout). Retries cover 408/409/429/5xx and I/O failures.
HandlersA list of DelegatingHandlers spliced into the HTTP pipeline. This is how middleware such as the refusal-fallback handler plugs in.
ResponseValidationWhen true, every response model is Validate()d eagerly. Off by default.
OpenTelemetryOpt-in tracing spans via OpenTelemetryOptions.
WithOptions(o => …)Returns a new client sharing the transport, with a modified ClientOptions. Every service has the same method for per-call overrides.
WithRawResponseA parallel client whose methods return HttpResponse<T> instead of the model (see §7).

ClientOptions is a record struct, so the WithOptions modifier works with with expressions:

var patient = client.WithOptions(o => o with
{
    Timeout = TimeSpan.FromMinutes(30),
    MaxRetries = 5,
});

Services

src/Anthropic/Services/ · Services/Beta/ · Services/Organization/

Each API resource is an interface/implementation pair (IMessageService / MessageService), and nested resources hang off their parent as properties. Every service also has a …WithRawResponse twin. The full tree reachable from the client:

client ├─ Messages Create · CreateStreaming · CountTokens │ └─ Batches Create · Retrieve · List · Cancel · Results … ├─ Models Retrieve · List ├─ Files ├─ Skills ├─ UserProfiles ├─ Organization ApiKeys · Invites · Users · Workspaces · Analytics · Federation … └─ Beta ├─ Messages Create · CreateStreaming · CountTokens · ToolRunner · Thread · Batches ├─ Agents · Environments · Sessions · Deployments · DeploymentRuns Managed Agents ├─ Vaults · MemoryStores · Dreams · Tunnels · Webhooks └─ Models · Files · Skills · UserProfiles · Organization

Method naming is regular: Create, Retrieve, Update, List, Delete, plus a …Streaming suffix for SSE endpoints (which return IAsyncEnumerable<T> rather than Task<T>). All methods take an optional CancellationToken.

Params & models

src/Anthropic/Models/ · Core/ParamsBase.cs · Core/JsonModel.cs · Core/ModelBase.cs

Namespaces mirror the API: Anthropic.Models.Messages (392 files), Anthropic.Models.Files, Anthropic.Models.Beta.Messages, Anthropic.Models.Beta.Sessions, and so on. Two base types matter:

ParamsBase

Request records such as MessageCreateParams. Carries the body plus path, query and header parameters. Use object initialisers with required init properties.

JsonModel : ModelBase

Response and nested types such as Message, Usage, TextBlock. Immutable record classes backed by the raw JSON, exposed as RawData. Validate() checks required fields.

Because models keep the raw JSON, fields the SDK version does not know about survive a round trip. When you relay API output back into a request, pass the model through rather than rebuilding it from typed properties.

Immutable by design. Build a request once, then use with for variations: var next = parameters with { MaxTokens = 4096 };. On spec-nullable properties (CacheControl, Container, ContextManagement), assigning null sends "prop": null rather than omitting it.

Unions & enums

Models/Messages/ContentBlock.cs · Core/ApiEnum.cs

Discriminated unions

C# has no native sum type, so polymorphic API fields are generated as union classes. ContentBlock can hold a TextBlock, ThinkingBlock, ToolUseBlock, ServerToolUseBlock, WebSearchToolResultBlock and seven more. Each union offers four ways in:

// 1. Try-pattern, one variant at a time
if (block.TryPickToolUse(out var toolUse)) Run(toolUse.Name, toolUse.Input);

// 2. Exhaustive callback per variant
block.Switch(text => …, thinking => …, redacted => …, toolUse => …, /* … */);

// 3. Exhaustive projection
string kind = block.Match(text => "text", thinking => "thinking", /* … */);

// 4. Raw object for LINQ / pattern matching
var texts = response.Content.Select(b => b.Value).OfType<TextBlock>();

The same shape is used everywhere: stream events (RawMessageStreamEvent.TryPickContentBlockDelta), deltas (TryPickText, TryPickThinking), tool definitions (ToolUnion), and Managed Agents events (TryPickSessionStatusIdleEvent). Unions also have implicit conversions from each variant, so you rarely write new ContentBlock(...).

Open enums: ApiEnum<TRaw, TEnum>

Enum-valued fields like Message.StopReason are typed ApiEnum<string, StopReason> so that values added to the API later do not break deserialisation.

if (response.StopReason?.Value() == StopReason.ToolUse) { … }   // typed compare
string wire = response.StopReason!.Raw();                         // "tool_use"
Model = Model.ClaudeOpus5_5,     // implicit from the C# enum
Model = "claude-opus-5-5",       // or from the raw string
Gotcha. ToString() on models and enums returns JSON (quotes included). Compare with .Value() or .Raw(), never ToString().

Streaming

Core/Sse.cs · Helpers/SseAggregator.cs · Helpers/MessageContentAggregator.cs · SseAggregatorExtensions.cs

CreateStreaming returns a lazy IAsyncEnumerable<RawMessageStreamEvent>. The request is sent when you start enumerating, and enumerating it twice sends two requests.

await foreach (var ev in client.Messages.CreateStreaming(parameters))
    if (ev.TryPickContentBlockDelta(out var d) && d.Delta.TryPickText(out var t))
        Console.Write(t.Text);

Two helpers fold events back into a complete Message, the same type a non-streaming call returns:

// Whole stream → one Message
Message message = await client.Messages.CreateStreaming(parameters).Aggregate();

// Live events AND the final Message
var aggregator = new MessageContentAggregator();
await foreach (var ev in client.Messages.CreateStreaming(parameters).CollectAsync(aggregator))
    { /* render deltas */ }
Message final = aggregator.Message();

Beta has mirrors: BetaMessageContentAggregator, and BetaManagedAgentsEventAggregator for session event streams.

Raw responses & pagination

Core/HttpResponse.cs · Core/IPage.cs · IPageExtensions.cs

WithRawResponse

Any call can go through client.WithRawResponse to get an HttpResponse<T>: status, headers, RequestID, WorkspaceID, and a lazy Deserialize(). Streaming calls return StreamingHttpResponse<T>.

using var raw = await client.WithRawResponse.Messages.Create(parameters);
Console.WriteLine(raw.RequestID);
Message message = await raw.Deserialize();

IPage<T>

List endpoints return a page type (ModelListPage, …) implementing IPage<T> with Items, HasNext() and Next(). The Paginate() extension walks all pages as an async stream:

var page = await client.Models.List();
await foreach (var model in page.Paginate())
    Console.WriteLine(model.ID);

Helpers

src/Anthropic/Helpers/ · Helpers/Beta/ · AnthropicClientExtensions.cs · src/Anthropic.Mcp/

Hand-written conveniences layered over the generated surface. Anthropic.Helpers and Anthropic.Helpers.Beta are the namespaces to import.

ConstructPurpose
Messages.Create<T>(…) stableStructured output. Infers a JSON schema from T (tunable with [SchemaClass]/[SchemaProperty]), returns StructuredMessage<T>; call .Content[0].Parsed().
BetaToolRunner betaThe agent loop. client.Beta.Messages.ToolRunner(params, tools) is an IAsyncEnumerable<BetaMessage>, one item per turn, running tools until the model stops. Mutate mid-run with SetParams, PushMessages, AddTools, RemoveTools, CompactBeforeNextTurn.
BetaRunnableTool betaA tool = a BetaTool definition plus a Run delegate. Throw BetaToolError to return is_error: true to the model.
BetaAbstractMemoryTool betaBase class for implementing the memory tool's storage backend.
BetaMessageThread betaclient.Beta.Messages.Thread(params) keeps conversation state server-side. Send, SendStreaming, Fork, typed Thread<T>.
BetaRefusalFallbackHandler + BetaFallbackState betaClient-side retry on another model when a request is refused. Added through Handlers; used where server-side Fallbacks isn't available.
AsIChatClient(model) stableAdapts the client to Microsoft.Extensions.AI.IChatClient, so MEAI pipelines (function invocation, caching, logging) work unchanged. Also AsIHostedFileClient() and ToolUnion.AsAITool().
BetaMcp betaIn Anthropic.Mcp: ListToolsAsync / Tools turn an MCP client's tools into IBetaRunnableTools for the tool runner.
 
var weather = new BetaRunnableTool
{
    Name = "get_weather",
    Definition = new BetaTool { Name = "get_weather", Description = "…", InputSchema = schema },
    Run = (toolUse, ct) => Task.FromResult<BetaToolResultBlockParamContent>("18°C, cloudy"),
};

var runner = client.Beta.Messages.ToolRunner(new MessageCreateParams
{
    Model = Anthropic.Models.Messages.Model.ClaudeOpus5_5,
    MaxTokens = 1024,
    Messages = [new BetaUserMessageParam { Content = "Weather in Paris?" }],
}, [weather]);

await foreach (BetaMessage turn in runner)
    Console.WriteLine(turn.StopReason);

Exceptions

src/Anthropic/Exceptions/ · Exceptions/AnthropicExceptionFactory.cs

Everything the SDK throws on its own behalf derives from AnthropicException. HTTP status codes map to concrete subclasses through AnthropicExceptionFactory, so you can catch from most to least specific:

AnthropicException ├─ AnthropicServiceException service reported an error · .ErrorType │ ├─ AnthropicApiException non-2xx · .StatusCode · .ResponseBody │ │ ├─ AnthropicBadRequestException 400 │ │ ├─ AnthropicUnauthorizedException 401 │ │ ├─ AnthropicForbiddenException 403 │ │ ├─ AnthropicNotFoundException 404 │ │ ├─ AnthropicUnprocessableEntityException 422 │ │ ├─ AnthropicRateLimitException 429 │ │ ├─ Anthropic4xxException / Anthropic5xxException other ranges │ │ └─ AnthropicUnexpectedStatusCodeException │ └─ AnthropicSseException error event inside a 200 stream ├─ AnthropicIOException transport failure · retryable ├─ AnthropicInvalidDataException JSON won't fit the model · failed Validate() └─ WorkloadIdentityException … feature-specific

Outside the family by design: ArgumentException for bad arguments, NotSupportedException for operations a platform client can't offer, and OperationCanceledException for cancellation and timeouts.

try { await client.Messages.Create(parameters); }
catch (AnthropicRateLimitException e) { /* back off; e.ResponseBody */ }
catch (AnthropicApiException e) when ((int)e.StatusCode >= 500) { /* retry later */ }
catch (AnthropicIOException) { /* network */ }

Credentials

src/Anthropic/Credentials/ · Core/ClientOptions.cs

The no-arg constructor looks for credentials in this order, first match wins:

#Source
1ANTHROPIC_API_KEY
2ANTHROPIC_AUTH_TOKEN
3The active or ANTHROPIC_PROFILE-selected profile written by ant auth login (CredentialsFileProvider)
4Workload Identity Federation env vars (WorkloadIdentityCredentials), which exchange a JWT for an access token and refresh it

To supply your own, set ClientOptions.Credentials to any IAccessTokenProvider. StaticTokenCredentials, WorkloadIdentityCredentials and AnthropicCredentials are the built-in implementations; TokenCache handles refresh.

Platform packages

src/Anthropic.Bedrock · Anthropic.Vertex · Anthropic.Foundry · Anthropic.Aws · Anthropic.GoogleCloud · Anthropic.Mcp

Each cloud client is a separate NuGet package and a subclass of AnthropicClient, so client.Messages.Create(...) and the rest of the surface are unchanged. Internally, each one inserts an adaptation DelegatingHandler that rewrites URLs, moves model into the path where needed, signs requests, and strips first-party API keys so they never reach a third-party host.

Stable vs Beta

The SDK mirrors the API's split by name and namespace. Nothing is shared between the two type families, so the beta surface can change without touching stable code.

StableBeta
Serviceclient.Messagesclient.Beta.Messages
NamespaceAnthropic.Models.MessagesAnthropic.Models.Beta.Messages

AggregatorMessageContentAggregatorBetaMessageContentAggregator

The beta MessageCreateParams lives in Anthropic.Models.Beta.Messages and has the same name as the stable one. With both namespaces imported, alias one: using Messages = Anthropic.Models.Messages;. Helpers that only work on beta types (tool runner, threads, fallbacks, Managed Agents aggregators) carry the Beta prefix.
